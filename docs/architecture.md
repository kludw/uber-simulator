# Architecture

What lives where and how it connects. Behavior: [spec.md](spec.md). Why: [ADRs](adr/README.md). Terms: `.claude/skills/domain/SKILL.md`.

Current state: milestones 2 to 29 done. `bun run sim` runs everything in one process over an in-memory bus, or with `--bus nats` each service on its own NATS connection. Each service also runs as its own process over NATS ([0019](adr/0019-single-package-multiple-entrypoints.md), [0028](adr/0028-nats-bus-subjects-and-delivery.md)), all spawned by `bun run dev`. Integration tests check invariants on NATS runs. `bun run ui` serves the browser UI, which subscribes to NATS events over WebSocket. The persister (also spawned by `bun run dev`) stores every event from a JetStream stream into the ClickHouse `events` table; `bun run report` queries it per run. Dispatch matches greedily or in batches, chosen per run (`--matching` / `MATCHING`, [0030](adr/0030-batched-matching.md)); `bun run sim -- --compare` runs both in process on one seed side by side. Rider demand model (uniform or `city` hotspots, [0031](adr/0031-hotspot-demand.md)), demand rate, and fleet size are chosen per run too (`--demand` / `DEMAND`, `--requests-per-minute`, `--drivers-per-shard`), and so are driver shifts (`--shifts` / `SHIFTS`, [0032](adr/0032-driver-shifts.md)) and preferences (`--preferences` / `PREFERENCES`, [0035](adr/0035-driver-preferences.md)). Dispatch splits into one process per region of the grid, each owning its tile's trips and drivers (`--regions` / `REGIONS`, default `1x1`, [0050](adr/0050-split-dispatch-by-region.md)). `bun run bench` measures per-tick cost in process and `bun run loadtest` whether the distributed stack keeps real time at a fleet size ([performance.md](performance.md)). `bun run replay` republishes a stored run on `replay.<runId>.*` and the UI watches it with `?replay=<runId>` ([0034](adr/0034-replay.md)). `bun run demo` starts local infra, `bun run dev` and `bun run ui` together on demo defaults ([0053](adr/0053-scale-the-ui-in-the-browser.md)). Local NATS and ClickHouse run via Docker Compose (see Local infra).

| Driver brain | `src/driver/brain.ts` | one shard of drivers: placement, wandering, offers, driving to pickup/dropoff, shifts (`shifts` start config: `always_online` default, or alternating online/offline periods from per-driver streams `shift:<driverId>:<n>`; a driver goes offline only when idle, offline drivers stay put and decline every offer), preferences (`preferences` start config: `accept_all` default, taking no streams, or `picky`: per-driver max pickup distance from stream `preference:<driverId>`, random declines from `offer:<tripId>:<driverId>`, checked only for idle drivers), trip confirmation (`at_pickup` / `at_dropoff` sends `confirm_trip` every 10 ticks without a trip event, acts on the matching `trip_status`). Stops ([0056](adr/0056-pool-two-riders-going-the-same-way.md)): the four busy states keep their current stop as their own fields (`tripId`, `pickup` or `dropoff`) and add `trips` (the one or two trips held, each with its `pooled`) and `next` (the stops after the current one), both built on a change of stop and shared across ticks, never rebuilt per tick (one trip: its dropoff is `next` until pickup, then none). A busy driver holding one pooled trip accepts a pooled offer in its trip's region (a join, no preference draw): the partner's pickup stays current if still ahead, then the joining pickup, then the dropoffs in `partnerDropsFirst` order; a driver waiting at the partner's dropoff drops it first, then serves the joining trip. Completion, cancel, expiry and `released` drop that trip and its stops (`withoutTrip`): on to the next stop if the current one was the trip's, idle after the last; cancel or expiry of a held trip with no pickup ahead is rejected (`trip_already_picked_up`). Regions (`regions` start config, one region by default, [0050](adr/0050-split-dispatch-by-region.md)): `en_route` / `at_pickup` / `on_trip` / `at_dropoff` keep the trip's region (its pickup's, from the offer), set on `offer_accepted` / `offer_declined` (the offer's pickup region), arrivals and `confirm_trip`; `driver.went_offline` and each `drivers.went_online` chunk carry their cells' region; each `drivers.moved` chunk the region owning its drivers (an idle driver's cell before the move, a busy driver's trip's); both chunked per region in index order; an idle driver declines an offer whose pickup region differs from its cell's; `offer_declined` carries `idleAt`, the driver's cell when idle, else null. Chase cells come from child stream `chase:<tick>`, taken once per tick only when a driver chases, so wander and placement draws on the shard's stream are not shifted and surge-off runs take no extra draw. Drivers kept in a map by driver ID, inserted in ID order and updated in place, so lookups don't scan and ticks still go in ID order. The shard's drivers come from start config `fleetSize`, `firstIndex`, `driverCount`; each record keeps its driver index, which its entries in `drivers.went_online` / `drivers.moved` carry ([0052](adr/0052-driver-indexes-in-moves.md)) | [0022](adr/0022-source-layout-and-brain-shape.md), [0025](adr/0025-driver-at-dropoff-state.md), [0032](adr/0032-driver-shifts.md), [0035](adr/0035-driver-preferences.md), [0036](adr/0036-scale-to-50k.md), [0041](adr/0041-confirm-trip-while-waiting.md), [0045](adr/0045-publish-driver-moves-in-batches.md), [0047](adr/0047-driver-moves-as-parallel-arrays.md), [0049](adr/0049-publish-drivers-going-online-in-batches.md), [0052](adr/0052-driver-indexes-in-moves.md), [0055](adr/0055-idle-drivers-chase-surge.md) |
| Dispatch brain | `src/dispatch/brain.ts`, `trip.ts` | owns every trip of its region: queue, offers, matching (`matching` start config: greedy default, or batched every `windowTicks`), pickup, completion, cancel. `regions` / `region` start config: the layout and the region it owns (one region by default). `fleetSize` start config: driver shards' count × driversPerShard; a `drivers.went_online` / `drivers.moved` with another `fleetSize` is rejected whole (`input_rejected`, `fleet_size_mismatch` with `expectedFleetSize`, logged by the shell), its drivers unknown until a matching message ([0052](adr/0052-driver-indexes-in-moves.md)). Keeps its drivers across ticks in the idle driver index, bounded to its region: cells from each entry of `drivers.went_online` / `drivers.moved`, by driver index (`placeDriverAt`); `driver.went_offline` drops a driver until it is back online (only same-tick stale offers reach it); `storeTrip`, the one place trips change, marks a driver busy from its offer until the offer or trip is over. Before a transition frees a driver, its input's cell updates the driver by ID (`placeDriver`, only a known driver, else it throws: these inputs come only from the busy driver): an `offer_declined`'s `idleAt` (null drops the driver), an arrival's or `confirm_trip`'s cell, only when the transition runs, so a driver whose crossing move was lost isn't kept idle at a stale cell inside the region ([0050](adr/0050-split-dispatch-by-region.md) item 6). Greedy asks the index for each queued trip's nearest idle driver in FIFO order, the offer making that driver busy; batched, on each window tick, passes the queued trips and the index's `nearestIdleSkipping` to `minCostMatchingByNearest`, unless more trips are queued than drivers are idle (`idleCount`): then it takes the idle drivers ordered by ID and reads them as flat coordinates to fill the dense solver's pickup distances ([0051](adr/0051-search-untouched-drivers-in-batched-matching.md)). `surge` start config (default off; `SimConfig.surge`): every 30 ticks, after matching and before offer expiry, it counts its unmatched trips (`requested`, by pickup's zone) against the index's idle drivers per zone (`idleCountsByZone`) and publishes `zones.priced` with its zones above 1.0 (`surgeOf`), so a zone cut by a region border is priced from the region's part; `trip.requested` carries the request's `surge` (1.0 if absent) and its `fare` (`fareOf`). | Idle driver index | `src/dispatch/idle-drivers.ts` | dispatch's drivers in its region (`startIdleDrivers(grid, fleetSize, region)`, the whole grid by default) across ticks, updated in place: one record per known driver in an array by driver index, the fleet's size long, and in a `Map` by ID for the inputs that name a driver by ID, set when first placed and cleared when dropped ([0052](adr/0052-driver-indexes-in-moves.md)); known cells, kept as x and y numbers (`placeDriverAt` by index on going online or moving, an index outside the fleet throws; `placeDriver` by ID for a known driver; `removeDriver` on going offline), busy drivers (`markBusy` only an idle driver, `markFree` only a busy one, else it throws; `nearestIdleSkipping(drivers, pickup, skip)` is the same search skipping the drivers a predicate holds for, returning the driver with its cell (batched matching's nearest untouched driver); `idleCount` counts the idle drivers; `idleCountsByZone` counts them per surge zone in one pass over the buckets, no collecting or sorting (pricing, [0054](adr/0054-price-trips-with-zone-surge.md)); `idleDriversById` lists them for batched's dense case. A driver cell off the grid (bad input) goes to the nearest edge bucket, distances still from its true cell, so the result stays exact; a pickup off the grid takes the linear scan. Tuning measured in [performance-history.md](performance-history.md#grid-index-tuning), bucket size retuned in [Move handling cut](performance-history.md#move-handling-cut) | [0036](adr/0036-scale-to-50k.md), [0048](adr/0048-keep-idle-drivers-across-ticks.md), [0050](adr/0050-split-dispatch-by-region.md), [0051](adr/0051-search-untouched-drivers-in-batched-matching.md) |
| Matching solver | `src/dispatch/matching.ts` | `minCostMatching(rows, columns, { ofRow, ofColumn })`: pure Hungarian solver for the batch assignment, maximum cardinality first, then least total cost; an `Infinity` cost is a pair not allowed; throws on negative / non-integer costs. Asks the caller to fill one row's costs at a time (one column's when rows outnumber columns) and never stores the matrix, so memory is O(rows + columns) ([#213](https://github.com/kludw/uber-simulator/issues/213)). Runs on the rectangular problem (smaller side as rows, transposed if needed, no padding): O(rows² × columns). Used by dispatch in batched mode when more trips are queued than drivers are idle. `minCostMatchingByNearest(trips, nearest, grid)`: same objective for queued trips (pickup, excluded drivers) over idle drivers it never lists: exact shortest augmenting paths with potentials over the drivers some path has reached (touched), plus each visited trip's nearest untouched allowed driver from the `nearest(pickup, skip)` callback (cached per trip until that driver is touched), else any untouched driver at the sentinel cost (trips × (grid width + height − 2) + 1, which assumes every cell is on the grid: an off-grid cell is bad input, and with one a batch may get fewer pairs than the dense solver's); a trip found to have no allowed untouched driver isn't queried again in the batch; needs at least as many idle drivers as trips, else throws. Doesn't import the index. Used by dispatch in batched mode otherwise | [0030](adr/0030-batched-matching.md), [0033](adr/0033-scale-fixes.md), [0051](adr/0051-search-untouched-drivers-in-batched-matching.md) |

Off: no `willingness` draw, no `surge` ([0054](adr/0054-price-trips-with-zone-surge.md)) | [0016](adr/0016-initial-domain-model.md), [0022](adr/0022-source-layout-and-brain-shape.md), [0036](adr/0036-scale-to-50k.md) |

## Data flow

```
bun run sim -> main.ts --config--> runner
runner: start shards, dispatch, riders on in-memory bus
  each tick: publish clock.ticked, drain
    bus --message--> service shell --input--> brain.decide --outputs--> shell --publish--> bus
    every published message --> onMessage (event log only with keepEventLog)
  --bus nats: same, each service on its own NATS connection, runner records every type,
    waits for 10 ms of quiet instead of drain
runner --each message--> summary (+ invariant checker) --> main.ts prints, exits (no event log kept; --bus nats: runner --{ eventLog, rejected }--> summarize)
--compare: runner twice (greedy, batched), summarize each --> compareSummaries --> main.ts prints table, exits
```

Separate processes (`bun run dev`):

```
dev.ts --Bun.spawn, RUN_ID, REGIONS--> dispatch-0..k-1, riders, driver-shard-0..n-1, clock (one process each, own NATS connection)
each: process shell --connect--> NATS bus --> service wiring --> service shell + brain
clock: wait CLOCK_START_DELAY_MS, then clock.ticked every 1 s / SPEED --> NATS sim.events.clock.ticked
every message: publisher --NATS subjectFor, Run-Id header--> services subscribed to its type (0042) --> its brain
```

Persistence (`bun run dev` spawns the persister; ADR 0029):

```
publisher --NATS sim.events.<entity>.<verb>, Run-Id header--> JetStream stream SIM_EVENTS (kept 24 h)
persister: durable consumer `persister` --fetch <= 10,000 msgs or 1 s (next fetch runs meanwhile, ADR 0044)--> parse --toRow--> insertEvents (async insert, wait)
  insert ok --> ack batch; insert failed --> log, retry (1, 2, 4, 8 s), else leave unacked --> redelivered after 60 s
ClickHouse events (ReplacingMergeTree on run_id, type, tick, stream_seq): redeliveries collapse; exact reads use FINAL
bun run report --> listRuns / runReport --SELECT ... FINAL--> events --> printed
bun run replay --> readRunEvents --SELECT ... FINAL--> events --paced by tick--> NATS replay.<runId>.sim.events.*
readRunEvents --SELECT ... FINAL ORDER BY tick, stream_seq, page by page--> parseMessage --> { tick, streamSeq, message }
```

Events published while the persister is down wait in the stream; core-NATS subscribers (services, UI) never wait on it.

Browser UI (`bun run ui`):

```
serve.ts --GET /--> index.html + bundled main.ts; --GET /config.json--> { natsWsUrl, regions }
main.ts --subscriptionFor(?replay=)--> subject: sim.events.> (live) | replay.<runId>.sim.events.> (replay)
main.ts --wsconnect NATS_WS_URL--> subscribe subject --parseMessage--> applyEvent --> view
view --> startRenderer.show (canvas, each animation frame: dots, or above 10,000 drivers heatmapOf once per tick) + panelRows (side panel)
```

The UI only subscribes; it builds its view from events alone and joins mid-run (ADR 0020). Live and replayed events take the same path after the subscription, so the view and renderer can't tell them apart (ADR 0034).

The start delay is what orders tick 1 after the other services subscribed; nothing waits for them explicitly. Nothing orders dispatch's subscriptions before the shards' start-up `drivers.went_online` either (one message per 5,000 drivers, [0049](adr/0049-publish-drivers-going-online-in-batches.md)): dispatch can miss some or all of them and learns those drivers from their tick-1 `drivers.moved` entries, before it can match the first requests on tick 2 ([0043](adr/0043-learn-drivers-from-moves.md), [Start-up race](performance-history.md#start-up-race)).

Regions (milestone 21, [0050](adr/0050-split-dispatch-by-region.md)): riders and driver shards set the `region` of every message dispatch takes, published on `<subject>.region-<k>`. Shards route moves by the ownership rule (an idle driver's to its previous cell's region, a busy driver's to its trip's) and idle drivers decline offers from other regions. Each dispatch instance (`dispatch-<k>`) is bounded to its region (its index keeps only that region's drivers, busy ones until freed) and subscribed only to its region's messages plus `clock.ticked`; every other subscriber takes all regions (`<subject>.*`). The runner starts one dispatch per region of `SimConfig.regions` (`--regions` for `bun run sim` and `bun run bench`, default `1x1`); over NATS, `bun run dev` (`REGIONS`) and `bun run loadtest` (`--regions`) start one dispatch process per region (`REGION_INDEX`), every process from the one `REGIONS` value (`serviceProcesses`).

Services never call each other: commands (`request_trip`, `cancel_trip` from riders; `confirm_trip` from drivers waiting at a pickup or dropoff, [0041](adr/0041-confirm-trip-while-waiting.md)), offers, replies (incl. `trip_status` to `confirm_trip`), and events are all bus messages. Dispatch is the only source of `trip.*` events ([0018](adr/0018-dispatch-matching-via-offers.md)). Offers reach every shard (`sim.offers.*`); only the shard owning the driver passes them to its brain (its `accepts`).

## Where decisions live

- Grid geometry, distance, moves, spec grid size (`specGrid`): `src/shared/grid.ts`.
- Region layout, numbering, and which region a cell is in: `src/shared/regions.ts` ([0050](adr/0050-split-dispatch-by-region.md)).
- Surge zones (size, numbering, a zone's part in a region, zone count, zone distance), the surge formula, the fare formula, `baseSurge` (1.0: no price) and `dollars` (cents as printed and shown): `src/shared/surge.ts` ([0054](adr/0054-price-trips-with-zone-surge.md)). Pricing (when, what is counted, the trip's price): `src/dispatch/brain.ts`; idle drivers per zone: `src/dispatch/idle-drivers.ts`; quotes, max surge, and declines: `src/rider/brain.ts`. Chase (reach, nearest surge area, when drivers re-pick): `src/driver/brain.ts` ([0055](adr/0055-idle-drivers-chase-surge.md)). Switched by `SimConfig.surge` (`--surge`, `SURGE`, default off); revenue outside dispatch: `src/sim/summary.ts` (base fare without a `fare`) and `src/analytics/report.ts` (event `fare` only).
- Pooling rules ([0056](adr/0056-pool-two-riders-going-the-same-way.md)): whether a pooled trip can join a partner's driver (join ETA via the partner's pickup while still ahead, cap 120; detour limit 1.5 × direct for both riders, the partner's ride so far in ticks since pickup; a driver at an aboard partner's dropoff drops it first) and its join ETA (`joinEtaOf`), the dropoff order (`partnerDropsFirst`): `src/shared/pool.ts`; the pooled fare (25% off, rounded once): `fareOf` in `src/shared/surge.ts`, which takes the trip's message so its `pooled` comes with it; `pooled` (true or absent) on `request_trip`, `trip.requested` and `offer`: `src/shared/messages.ts`. The driver brain orders a join's dropoffs with `partnerDropsFirst` (#347). Joins (#348): `src/dispatch/brain.ts`. It counts its open pooled trips (`pooledOpen`) and, only while that is above 0 on a matching tick with a trip queued, builds the tick's partners in one pass over its trips (pooled, holding a driver no other trip holds, that driver online in the idle driver index: `busyDriverCell`); a queued pooled trip takes the partner with the least `joinEtaOf` (ties to the earlier requested), whose driver then holds two. Greedy tries the join before the nearest idle driver; batched joins before and after batched matching, and a pooled trip just offered an idle driver is a partner for the rest of the tick. Per driver holding two trips, one set entry (`holdingTwo`): `storeTrip` adds it when a pooled trip's offer goes to a busy driver (`isBusy`) instead of `markBusy`, and removes it when a pooled trip leaves such a driver instead of `markFree`, so a driver is freed after its last trip. Per picked-up pooled trip, its pickup tick (`pickedUpAt`): the partner's ride so far is dispatch's last tick minus it. With pooling off all three stay empty.
